# iPhone SE 2nd generation (d79ap) port run, iOS 27.2.1 `24B156`

First device run of the `iphone12,8-d79ap-24B156` experimental profile, on an
iPhone SE 2nd generation (iPhone12,8, CPID 0x8030, board 0x10, ECID withheld).
Host: Apple Silicon Mac, macOS 26.7.1, usbliter8 on Waveshare RP2350 USB-A
(the same board the profile assumes for every A12/A13 device).

The commands as they were actually run, in order, with what the phone did at
each stage. Release-mode CLI throughout. The one code change this run covers
is the profile itself plus its regression test; nothing else in the tree was
touched.

## Profile

`survey --guards` on the single-board `iPhone12,8_27.2.1_24B156_Restore.ipsw`
produced the guards committed in the profile. Measured, not assumed: the
launchd digest matches the shared 24B156 rootfs (`0776cff2…`, same as n104ap),
while the launchd cache digest is this board's own (`a9d365ef…`, differs from
n104ap's `a07c37e3…`). Daemon count 732 and Setup method count 64 landed on
the same values as the reviewed iPhone 11 entry by measurement.

## Prepare and build the CFW

```bash
WORK_DIR=/Users/sayaome/liter8-work .build/release/liter8 fw prepare \
  --file /Volumes/…/iPhone12,8_27.2.1_24B156_Restore.ipsw
# verified extracted firmware: iPhone12,8_27.2.1_24B156_Restore

WORK_DIR=… .build/release/liter8 fw make-cfw --experimental
```

All six restore artifacts resolved, patched and verified on the first run with
no resolver changes:

```
PASS  ibss-restore / ibec-restore / devicetree-restore /
      kernel-restore / restore-ramdisk / txm-restore
[+] every built CFW artifact matches its post-patch record
```

The d79ap DeviceTree and the board firmware set (`adc-zelus-d79`,
`D79_Multitouch`, `aopfw-iphone12caop`, `WirelessPower.iphone12c`) were taken
from the manifest identity; no component mapping was hand-written.

## Restore

Phone in pwn DFU via usbliter8 (PWND observed on the host before starting).

```bash
WORK_DIR=… .build/release/liter8 fw restore-cfw --experimental
```

First attempt, no retries. Ended `Status: Restore Finished`, and the managed
TSS proxy captured a verified APTicket (`apticket.im4m`) — 27.2.1 was signed at
the time of the run.

## SSHRD, bootstrap, provisioning

```bash
WORK_DIR=… .build/release/liter8 fw get-rd --experimental
WORK_DIR=… .build/release/liter8 fw boot-rd --experimental
WORK_DIR=… .build/release/liter8 fw bootstrap --check --experimental
WORK_DIR=… .build/release/liter8 fw bootstrap --experimental
WORK_DIR=… .build/release/liter8 fw prepare-rootfs --experimental
WORK_DIR=… .build/release/liter8 fw provision --experimental
WORK_DIR=… .build/release/liter8 fw unmount-rootfs --experimental
```

Mounted rootfs appeared as `/Volumes/RaveB24B156.D79OS`. `provision --check`
failed before provisioning on a fresh install (sftp-server ABSENT) — that is
the pre-install state the real `provision` then resolves; the README order
assumes a reviewed profile where the check pre-flights installed state.

## Normal boot and finalization

```bash
WORK_DIR=… .build/release/liter8 fw get-boot --experimental
WORK_DIR=… .build/release/liter8 fw boot --experimental
```

USB enumerated as a normal-mode iPhone ~25 s after the chain was sent;
`ideviceinfo` reported `27.2.1`.

```bash
WORK_DIR=… .build/release/liter8 fw finalize --check --experimental   # incomplete
WORK_DIR=… .build/release/liter8 fw finalize --experimental           # complete
WORK_DIR=… .build/release/liter8 fw finalize --check --experimental   # complete
```

Finalize reported SpringBoard restart, PosterBoard repair watcher running, and
`post-boot finalization is complete` on the recheck.

## Repeat boot

Full power-off path: reboot to recovery (the tethered fallback), then
re-pwn with usbliter8 and `fw boot --experimental` again. USB enumerated as
iPhone ~25 s after the chain was sent, `27.2.1` again. Both boots work; the
"first boot is luck" failure mode was not observed.

## d79ap-specific observations

- **Haptic Home button is dead** (no SEP), and unlike iPhone 11 there is no
  gesture navigation — Setup's Quick Start screen cannot be dismissed without
  a Home press. AssistiveTouch had to be enabled by hand over SSH: write
  `AssistiveTouchEnabledBySystem` / `AssistiveTouchEnabled` into
  `/var/mobile/Library/Preferences/com.apple.Accessibility.plist`, then
  `killall cfprefsd assistivetouchd SpringBoard`. Respring alone without
  killing cfprefsd did not surface the button. An iOS 27.2.1 host `plutil` is
  not available on this install; the plist was written as XML over a root
  SSH connection. This branch ships the follow-up now: `finalize.sh` enables
  AssistiveTouch for profiles that set `enableAssistiveTouch` (pull the plist,
  merge with plistlib on the Mac, push, restart cfprefsd). This run applied
  the change by hand before that step existed; the next erase cycle exercises
  the scripted path end to end.
- Boot plan shipped empty and the first boot worked, so no iBSS display
  additions were needed for this board (as far as one boot pair can tell).
- Known Liter8 limits apply unchanged: no SEP/passcode, no Apple services
  outside the App Store, no cellular data. Out of scope for this run.

## State after this run

Profile left `experimental`. Promoting it to `reviewed` would want at minimum
a second operator, longer soak, and TrollStore/app-launch checks that were not
part of this run.
